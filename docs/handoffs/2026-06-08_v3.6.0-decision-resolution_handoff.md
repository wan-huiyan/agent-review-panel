## 2. The design in one paragraph
Add a human-in-the-loop layer to the review panel: a single **grill engine**
(grill-me pattern inlined, no hard dep) with **three entry points** — ① upstream
(Phase 0, plan-mode: lock open decisions before reviewers launch), ② downstream
terminal (Phase 17: resolve judge `[USER-DECISION]` items), ③ downstream HTML
ingest (annotate each finding in the HTML report → export a self-contained
feedback bundle → paste back → questions route into the grill). Plus a judge
`[USER-DECISION]` label guarded by the Phase 14.5 gate, and a
`plan-review-integrator` handoff. **last30days `[COMMUNITY-SIGNAL]` is explicitly
deferred to v3.7.0** (spec §10).

## 4. Key decisions
| Decision | Resolution | Rationale |
|---|---|---|
| Placement | Post-report optional step (+ upstream Phase 0) | Anti-bloat; "bookend not internal"; debate ran in only 1/51 audited runs |
| Resolution-queue scope | Judge-deferred `[USER-DECISION]` items only | Cleanest signal, shortest interview |
| Output | Record (`state/phase_17_*.md`) + offer plan-review-integrator | Don't mutate the verified report |
| HTML feedback bundle | **Self-contained** (carries finding title) | Async paste-back; `state/`/report path may be gone |
| Canonical ID | Finding IDs (`A1`/`B1`), not `AI-n` | One unambiguous key per annotatable card |
| `[USER-DECISION]` guard | Reuse Phase 14.5 gate (kick-back disguised verifiable Qs) | Stops judge laundering correctness as "tradeoff" |
| Scope/sequence | Grill bookend in v3.6.0; last30days → v3.7.0 | Two different axes (human-loop vs research-input) |
