### Key planning discoveries (baked into the plan — do not re-derive)
1. **The real version gate is `scripts/release-check.sh`, NOT `npm test`.** Plugin name is `roundtable` but the skill dir is `agent-review-panel`, so `manifest-consistency.test.mjs`'s marquee version checks (SKILL.md H1, `eval-suite.json` version) are **skipped**. release-check additionally enforces the SKILL.md HTML-footer instruction, a ROADMAP **v3.6.0 row**, a CHANGELOG `[3.6.0]` section, and **README test-count == actual `node --test` count** (so adding tests forces a README update). New test files must be registered in `package.json` `scripts.test`.
2. **The §3.2 guard is testable only as spec-presence**, not behavior (no LLM in CI). The plan ships the safety property as a **worked example of the guard firing** (a disguised-verifiable claim kicked back to `[DISPUTED]`) inside the Phase 14.5 prompt — the few-shot an LLM keys off — plus presence assertions. The PR must state the test verifies the guard is *specified*, not that it *fires*.
3. **Golden byte-stability** holds via a conditional `###` deferral subsection (the golden fingerprint only sees `## ` sections) + one new complete fixture; `[USER-DECISION]` must never appear as a numbered action item (would fail the action-item label regex `(VERIFIED|CONSENSUS|SINGLE-SOURCE|UNVERIFIED|DISPUTED)`).
4. **The bundle grammar** gets a reference `serializeBundle`/`parseBundle` round-trip test (mirrors the existing `parseReport` precedent) that also parses the documented example *out of* `prompt-templates.md` so prose and test can't drift — plus a hand-edited-tolerance case (§13).
5. **HTML rendering instructions** go in `prompt-templates.md` Phase 15.3 (the HTML agent reads that file), not SKILL.md.
